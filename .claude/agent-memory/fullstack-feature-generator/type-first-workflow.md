Source-of-truth `.ts` files live in `apps/main-backend/src/app/types/`:
- `main.types.ts` — shared types (imported by other type files)
- `auth.types.ts`, `merchant.types.ts`, `<feature>.types.ts` — per-feature API types
- `database.types.ts` — Supabase-generated, must NOT be regenerated by the type-first script

`yarn generate:types` (root) runs `apps/main-backend/scripts/type-first-workflow.js`:
1. For each `*.types.ts` (except `database.types.ts`), `@sinclair/typebox-codegen` emits a sibling `.schema.ts` in `apps/main-backend/src/app/schemas/`.
2. Concatenates all type files (stripped of imports/comments) into BOTH:
   - `apps/main-webapp/src/app/shared/types/api.types.ts`
   - `libs/api-services/src/types/api.types.ts`

**Why:** the project's agent system prompt forbids editing generated schemas manually; this script is the canonical way to regenerate them after touching `.types.ts`.

**How to apply:** After creating/editing any `*.types.ts` in `apps/main-backend/src/app/types/`, run `yarn generate:types` from the repo root. The script also runs `fix-schema-imports.js` to add `BaseUserRole` etc. imports to generated schemas that reference `main.schema.ts`. Note: the script log line says `smartschool-api` — that's stale text, ignore it.

After type-gen, rebuild `libs/api-services/dist/` declarations (`npx tsc -p libs/api-services/tsconfig.lib.json`) so the webapp's tsc resolves the updated `AuthUser` etc. via the dist `.d.ts`. See [[supabase-cli-access]] for why DB-driven type-gen isn't available.
